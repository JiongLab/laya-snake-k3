# K3 资源实测（2026-09-21）

结论：已安装的 v0.1.0 在本次无界面长蛇场景下，稳定 RSS 为 **1.88 GiB**，进程 CPU 时间约占 **2.46 个逻辑核**；1,200 步正常完成。不是最低内存、最大负载或完整兼容性认证。

## 环境与场景

- K3，16 个逻辑核，系统可见总内存 7,927 MiB，无 swap；启动前 available 为 6,127 MiB。
- Bianbu **4.0.7**；系统从旧测试的 4.0.5 升级，但 `python3-spacemit-ort=2.0.6`、`spacemit-onnxruntime=2.0.6`、`spacemit-tcm=3.0.0+5`、`python3-torch=2.9.1+dfsg-1~exp1ubuntu2` 未变。
- 使用已安装的 `/usr/bin/laya-snake-k3` 及独立用户环境；未更改后端、权重或系统依赖。其他任务已停用模型、游戏和编译；桌面系统仍运行，未清空操作系统文件缓存。
- 参数为 `--headless --initial-length 72 --steps 1200 --record <新的记录文件>`；其余沿用启动入口默认值：12×8、seed 7、方向单问题、SpaceMIT FP16、4 AI 线程。无终端画面渲染。

## 采样与统计口径

从创建应用进程开始，每秒读取该进程的 `/proc/<pid>/status`、`stat` 及各线程的 `task/<tid>/status`、`stat`。总计 158 个样本，监测耗时 158.68 秒。采样器本身是另一个轻量进程，不计入应用 RSS/CPU 数值，但可能带来少量测量扰动。

记录文件有写缓冲，因此不把“第一次能读到 frame”当作真实首帧时间。第一次可见记录在 36.13 秒；其后再留 10 秒，选取 **46.179–155.670 秒**为稳定窗口（110 个样本）。终点是四个 AI 工作线程仍在的最后样本；之后两个样本已经进入线程销毁、内存释放阶段，不能混入稳定运行统计。

CPU 利用率采用窗口两端累计 CPU ticks 的差，除以 `CLK_TCK=100` 和实际经过秒数，再乘 100。进程与线程分别计算；100% 表示一个逻辑核的全部时间，不表示硬件矩阵单元利用率。未测量功耗、温度、内存带宽或桌面渲染开销。

原始记录：[158 个进程/线程样本](resources/2026-09-21-samples.json)。其中 `seconds` 是从创建进程起的时间，`rss_kib`/`hwm_kib` 为 KiB，`ticks` 为累计用户态与内核态 CPU ticks，`allowed` 为线程亲和性，`cpu` 为采样时最近执行核。原始 PID/TID 仅用于关联同一次运行的线程，不包含用户名、路径或凭据。

## 结果

| 指标 | 实测值 |
|---|---:|
| 稳定 RSS 最小 / 中位 / 最大 | 均为 1,927.61 MiB |
| 全过程采样到的 VmHWM（含启动） | 1,927.61 MiB（1.8824 GiB） |
| 进程 CPU 平均 | 246.32% |
| 主线程 CPU 平均 | 99.89%，亲和性 0–7 |
| Core 8 的 AI 线程 | 36.67% |
| Core 10 的 AI 线程 | 36.55% |
| Core 12 的 AI 线程 | 36.66% |
| Core 14 的 AI 线程 | 36.54% |
| 排除首步的平均 / P95 / 最大推理耗时 | 109.86 / 115.50 / 120.90 ms |
| 第一步推理耗时 | 1,886.05 ms，不含此前模型加载 |
| 步数 / 填满棋盘次数 / 死亡 / 保护介入 | 1,200 / 1 / 0 / 0 |

四个 AI 线程在稳定窗口中的亲和性和采样到的执行核均与对应核编号一致。主线程与四个 AI 线程 CPU 时间相加约等于进程 CPU 时间；由于逐项读取并非原子快照，会有轻微统计误差。

RSS 含共享驻留页，不等于 PSS 或独占内存；未做系统级峰值统计。退出后 `getrusage` 给出的 maxrss 为 1,926.76 MiB，比 `/proc` 高水位小约 0.85 MiB（约 0.044%）；本文统一使用采样中可复核、较大的 `/proc` 值，不混用两个口径。稳定阶段未见 RSS 增长，不据此保证无限时运行无内存增长。

`du -sk` 的已分配空间：模型目录 1,294,060 KiB、venv 143,432 KiB、应用目录 14,644 KiB。模型和 venv 合计约 1.37 GiB；venv 包含额外验收依赖 pytest。复用的系统 PyTorch/ORT 等不在此总数中，记录、缓存和重复副本也另计，因此仍建议预留至少 5 GB，而不把该数当作系统总增量或最低磁盘要求。

## 验证边界

实际安装入口退出码为 0，`check-record.py --steps 1200` 校验了棋盘、动作、概率与最终统计的一致性。本节仅记录这次资源采样；随后独立环境补测已通过全部 121 输入精度回归、完整三问题测试和终端交互验收，详见 [VALIDATION.md](VALIDATION.md)。发布仍为候选版；原有 4.0.5 固定复现环境不因此自动改为任意 4.0.7 环境。
